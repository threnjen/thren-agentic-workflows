## No-Finding Categories

- No supported evidence of a committed live private key or well-known live-token form was found in the tracked current tree. Pattern hits were confined to test code designed around synthetic credential shapes. This is not a guarantee because history, entropy, binary, and dedicated secret scanning were unavailable.
- No network application, user-authentication service, session store, database, or API authorization layer is present; those controls are largely not applicable to this repository.
- No custom cryptographic primitive or insecure password-hashing implementation was found.
- The direct URL parser is bounded, network-free, validates schemes/ports/escapes, and keeps URL values out of decisions; supported literal-path/query cases have strong automated coverage.
- The production injection corpus contains fixed strings and short validated regular expressions; the repository benchmark reports 19 true positives, 0 misses, 0 false positives, and 0 high-tier false positives for its finite fixtures.
- No tracked CI workflow was present to assess for token permissions, untrusted checkout execution, artifact poisoning, or deployment-secret exposure.

## Cross-Cutting Risks

- The scanner currently treats bounded work as permission to pass unbounded content. Security limits must produce a conservative output decision, not merely a warning, when the unassessed portion remains model-visible.
- Filesystem trust is inconsistent: hook propagation received intermediate-symlink checks, while other propagation and logging writers still use ordinary path operations. A shared safe-write/delete primitive is needed across the repository.
- Support is strongest for automated Claude payload behavior. Live Claude, Codex, and OpenCode UI/loading/interception tests remain NOT RUN, and the accepted Codex limitation covers only the recorded Phase 02 successful-output subset.
- Regex detection remains defense in depth and is inherently bypassable. The three introduced High findings are more severe because they bypass detection through output shape or deterministic configured limits without inventing a new linguistic evasion.
- The code-review graph rated the broad Phase 02 delta at risk 0.60 with 82 inferred test gaps and no affected flows; this mismatch reinforces the need for explicit end-to-end security tests around adapters and serialized output shapes.

## Priority Remediation Order

1. **Release blockers:** close P2-SEC-01 through P2-SEC-03 and add end-to-end emitted-payload regressions before re-running the security gate.
2. **Existing High risks:** decide whether to remediate or explicitly accept REPO-SEC-04 through REPO-SEC-07; do not claim cross-harness or filesystem-wide security while they remain open.
3. **Filesystem integrity:** unify safe containment/no-follow behavior for propagation and audit logging (REPO-SEC-06 and REPO-SEC-08).
4. **Operational hardening:** fix stale config caching, bound Unity resource consumption, pin executable dependencies, and address the accepted latency failure.
5. **Defense in depth:** create audit files with explicit restrictive permissions.
