# Implementation Record: Deployment Guidance

## Summary

Replaced supported runtime-link deployment guidance with the settled fixed-point and managed-copy workflow. Evangelize now requires repository convergence, reviewed destination inventory, managed-copy reconciliation, honest per-harness reporting, and fresh-session discovery. Its Claude, Codex, and OpenCode variants were regenerated from source. Active setup and troubleshooting surfaces now direct operators to regular managed copies, while historical and security discussion remains explicitly classified.

## Sibling Features

- `02-propagation-convergence` supplies `propagate_until_converged` and the immediate zero-change gate.
- `03-cross-platform-destinations` supplies destination records and inventory resolution.
- `04-managed-copy-reconciliation` supplies `deploy_managed_copies_after_convergence` and ownership-aware copy reconciliation.
- `06-runtime-verification` consumes this guidance for scratch-home and live-platform evidence.

## Deviations from Plan

- Retained the three symlink-oriented setup filenames as compatibility entry points, but replaced their operational contents with managed-copy guidance. This avoids broken incoming references while retiring the behavior.
- Classified `codex/PILOT_SLICE_PLAN.md` as a historical, non-operational record.
- Did not modify `scripts/propagate_master_assets.py`; the settled upstream APIs were sufficient and no competing CLI adapter was introduced.
- Live native Windows and WSL runtime discovery remains assigned to Feature 06; this macOS run records those environments as runner-constrained.

## Gaps

- Live harness discovery and live native Windows/WSL deployment evidence are not produced by this documentation feature; Feature 06 owns those runs.
